# 发布说明

## 步骤

1. **收集改动**：读本次需求的 code-change 产物（提交列表与说明）；没有时用 `git.diff` 看改动。只写这次真正交付的内容。
2. **按读者分类**，每条一句话，写用户能感知到的变化，不写实现细节：
   - **新增**：新功能、新接口、新配置项
   - **改进**：体验、性能、文案上的变化
   - **修复**：说清楚以前哪里不对，现在怎样
   - **破坏性变更**：接口、配置、数据格式不兼容的地方，必须附迁移方法
3. **对照需求**：每条能对应到 PRD 或验收标准；对应不上的改动单独列在「其他」里，或在说明中指出。
4. **格式**：用 [references/template.md](references/template.md) 的结构。版本号、日期由上下文给出时填上，没有就留占位。

## 注意

- 不夸大：没测过的不写「大幅提升」。
- 不暴露内部信息：密钥、内部地址、用户数据不进发布说明。
- 破坏性变更放在最前面。
